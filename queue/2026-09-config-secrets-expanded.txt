Your agent's config files are the new .env, except worse, because nobody treats them like secrets.

.mcp.json and .claude/settings.json sit in plaintext on disk, get committed to repos, get pasted into team chats, and get inherited from templates found on GitHub. Then the agent reads them and acts on them with your credentials.

Here's the part that makes this worse than a leaked key. For Claude Code, .mcp.json and settings.json are documented execution vectors: the config file is how an attacker gets code to run in your agent's context. A leaked key exposes one service. A poisoned config file controls the thing that holds all your keys, and it does it through instructions the agent will follow voluntarily.

The numbers behind this:

1. A 2026 audit of 2,890+ agent skills found serious vulnerabilities in 41.7% of them.
2. Trend Micro found 492 MCP servers exposed to the internet with zero client authentication.
3. A GitGuardian sweep found over 24,000 secrets sitting in MCP-related config files on public GitHub, 2,117 of them still valid.

The "hardening Claude Code" prompts going viral aren't a fad. They're thousands of developers realizing they have no idea what their agent config actually contains.

Run the five-minute audit:

1. Inventory the three files. .mcp.json is the server roster: every entry can carry env blocks with API keys and autoApprove flags that let the server call tools without asking. settings.json and settings.local.json hold the permission rules. The system prompt is the third file, the one that decides what the model believes its job is.
2. Kill the plaintext keys. API keys in config env blocks move to a secrets manager, referenced not stored. Anything that was ever in a committed file counts as leaked, including git history. Rotation is cheaper than breach response.
3. Audit autoApprove flags. Every one is a tool call the agent makes without asking you. That flag was meant for convenience during development. In a shared repo it's an unattended execution permission.
4. Treat every installed skill and MCP server as untrusted code with a persuasion budget. It ships instructions the agent will follow, and 41.7% of them have serious bugs. Install from trusted sources, review what it instructs.
5. Re-audit after every install. Config rots. Yesterday's carefully scoped server is today's inherited template in a teammate's copy of the repo.

Then make it standing policy: agent config files are code, reviewed like code, versioned like code, and never copied between machines without reading them first.

The agent is only as trustworthy as the files it reads on startup.
